# 需求与范围

## 目标用户与场景

- 用户：使用 AI 盒子 Web 平台的安全监管/项目运维人员；前端页面与后端已由他人完成，AI 服务端需要保持既有接口。
- 场景：盒子上接入 36 路视频流，做安全帽/反光衣/救生衣/抽烟/人员聚集检测，输出检测图流、告警图片与告警视频。
- 现状替代方案：旧 Python 服务端一任务一进程，模型随任务加载，36 路时进程/内存/算力都撑不住，且存在内存泄漏。

## 非目标（本轮仍未做）

- 本轮不证明 36 路 1080p/10fps；压测条件是 640×360、1fps 检测、2fps 预览。
- 本轮不做 HTTP/WS async/线程池；仍线程每连接。
- 本轮不做告警 GC/磁盘配额。
- 本轮不做真实 ISC 服务器联调（盒子到身份服务器网络 refused）。
- 不改动盒子原厂 `/opt/sophon` 运行时，不刷机，不重装系统。
- 不把模型权重、SDK 二进制、告警图片/视频提交到仓库。
- 不在仓库中保存盒子密码、Web 账号、GitHub token 等凭证。
- 本阶段不做 INT8 重导/量化；反光衣先用 FP16（KI-001）。

## 约束

- 平台：BM1684X SoC，aarch64，Ubuntu 20.04 LTS；盒子 8 核、6.1 GiB 内存；根分区仅约 2.8 GiB 可用，`/data` 约 45 GiB。
- 网络：盒子不能访问外网；依赖包必须从工作区 `reference/release` 上传。
- 运行时：原厂 libsophon 0.5.1 + sophon-mw 0.12.0 正在使用；新 SDK 用 0.5.3 + 0.15.0 自包含并行部署。
- 性能底线：最终 36 路任务要稳定；单路输出给前端不超过 10 fps；模型调度要避免一任务一权重。
- 技术栈：新服务 C++17 + Boost.Beast + nlohmann/json + OpenSSL；硬件/多媒体用 sophon-sail。
- 模型：本阶段只支持 FP16；反光衣权重固定为 `yolov11s_fp16_1b_back_reflectivejacket_1.bmodel`，输入 `/255`。
- 合规：视频流、告警图片、账号密码均属敏感数据，日志和文档不得打印密码/token。
