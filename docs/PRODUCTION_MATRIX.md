## 2. 逻辑对比（链路 + 算法）

| 环节 | 我方实现 | 生产实现 | 是否一致 |
|---|---|---|---|
| 取流 | `IngestBridge`（libavformat 进程内拉流 → mpegts → 本地 UDP 22000+） | `StreamFactory` + `media_sdk`（进程内，无外部进程） | 形态一致，实现库不同 |
| ISC 接入 | `isc://` → 直连 RTSP/RTMP（单次 URL，失败轮换候选） | 同（ISC 客户端，streamType 0/1） | 一致 |
| 解封装 | 进程内 libavformat + mpegts 转封装 | media_sdk 内解封装 | 一致（都在进程内） |
| 解码 | **VPU 硬解** `h264_bm`/`hevc_bm`（帧在设备内存，`data[4]/[5]` 设备地址） | VPU 硬解（`DecodeInstance`，常驻不重建） | **已对齐**（路线 B 前是软件解码） |
| 帧缓冲 | 每任务复用 `BMImage`；设备侧 attach，无每帧 mmap | 每通道池化帧（常年 dmabuf 恒 133） | 已接近（见 §4） |
| 推理 | `bmrt_load_bmodel` + `bmrt_launch_tensor_ex`，输入零拷贝、输出张量复用 | `board::base_model`（bmodel） | 一致 |
| 调度 | FIFO 门票闸门 + 有界并发（默认 4）+ 多实例（同算法 ≤2） | 每任务异步 workLoop + 回调，赶不上就跳过该算法 | 语义一致 |
| 后处理 | YOLOv5/v11/Damo 自研 + 逐类 NMS + ROI + 跟踪 | 生产插件（同名算法） | 参数对齐见 §3 |
| 单通道预览 | 设备侧缩放 + 设备侧画框 + JPEG（CPU 编码） | `JpegEncoderInstance` 设备侧编码 | 我们仍有一次 CPU 编码（待优化） |
| 合流墙 | 4 组 × 3×3，设备侧画布 + `image_copy_to` + JPEG | `MergeInstance`（硬件合流） | 形态一致 |
| 告警图片 | 设备侧画框 + JPEG（1280×720 / 原尺寸） | 设备侧编码 | 一致 |
| 告警视频 | `TsSegmentRecorder`：TS 4s×6 分段环 → ffmpeg remux MP4 | `dump4`：每通道常驻，取 pre/post 进程内写 MP4 | 目标一致，实现不同 |
| 上报 | HTTP JSON + JWT，告警图/视频路径回填 | 同（`report_address`） | 一致 |
| 配置同步 | 每 2s 从后端 reconcile（任务/ROI/算法参数热更新） | 生产由 Web 下发到 `TaskInstance` | 一致 |
| 子码流切换 | 有（`/tmp/aidetect_auto_substream` 开关，默认关） | 生产按需主/子码流 | 未启用 |

## 6. 结论与差距

1. **逻辑栈已对齐**：取流/解码/推理/预览/合流/告警/上报的形态与生产一致；解码从软件换到 VPU 后，
   CPU 从 266~294% 降到 191~197%，dmabuf 从 500~660 降到 290 且恒定。
2. **单路 CPU 仍高于生产**（5.3% vs 3.3%）：主要差在
   ①预览/告警 JPEG 仍走 `bm_image_to_mat`+`cv::imencode`（CPU 编码，生产是设备侧）；
   ②每帧全尺寸 BGR_PLANAR 转换（生产按需缩放）。
   优化这两项预计可再降 1~2 个核。
3. **稳定性仍是短板**：生产连续 5 天 16 小时、1021 线程、dmabuf 0；我们本轮在修
   解码器生命周期崩溃（已改 `shared_ptr` + 读取前快照），需连续 24h 观察。
4. **线程模型**：生产 1021 线程（每通道多线程），我们 268~278，扩展性好但重连风暴时压力集中在少数线程。
5. **缺失的可观测项**：TPU/VPU 利用率（我方 `/get_occupancy` 返回 0）、端到端时延、告警召回/误报率。

## 7. 建议继续采集的参数（用户问「还有哪些参数」）

**性能**：解码帧率/丢帧率、每路 bitrate、CPU 每核分布与软中断、内存带宽、磁盘 IOPS/写入量（分段录制）、
设备内存（BM heap）占用与碎片率、VPP/JPU/VPU/TPU 利用率（连续采样）、温度与降频事件。

**时延**：相机→解码首帧、相机→检测完成、相机→告警上报、预览首帧时间、合流帧间隔抖动。

**业务**：告警召回率/误报率（按算法）、告警重复率、ROI 越界过滤命中率、跟踪 ID 切换率、
模型实例数与调度等待时间、帧间隔达成率（frameInterval 实际 vs 配置）。

**稳定性**：进程重启次数/僵尸次数、长跑 RSS 斜率（trim 前后）、dmabuf 斜率、重连次数/退避时长、
ISC 会话成功率、告警视频生成成功率/耗时、WS 并发客户端数、任务启动耗时。

**前端体验**：预览带宽（KB/s per client）、合流墙端到端帧率、图片清晰度（JPEG 质量）、
标签/框绘制正确率、黑白相机识别（区分源为黑白 vs 转换丢色）。
